# AI Generation Constraints — project-manuals

## 1. Sovereign Paths: AI MAY NOT write to these directly

The following paths are **sovereign** (human-approved only).
AI assistants MUST NOT create, edit, rename, or delete files in these paths.
If a change is needed, the AI must propose the change in a separate PR branch
and explicitly ask for human review.

```
constitution/                    # immutable governance constitution
constitution/invariants/         # invariant registry YAML files
.github/CODEOWNERS               # reviewer enforcement
.agent.md                        # this file
```

Any PR that modifies the above paths MUST have at least one human approval
before merging (enforced via CODEOWNERS).

---

## 2. Ledger Paths: APPEND ONLY — no overwrites, no deletes

```
phase14/data/ledger/             # canonical audit trail
phase14/data/*.audit.jsonl       # append-only event log
```

AI MUST NOT:
- Truncate or overwrite any `.jsonl` ledger file
- Delete ledger records, even "for cleanup"
- Rewrite history via `git push --force` on branches containing ledger data

AI MAY:
- Read ledger files for analysis
- Append new records in valid JSON Lines format conforming to `canonical-event.schema.json`

---

## 3. Schema Files: require human review

Files in `contracts/schemas/` define the closed contract surface.
AI MAY propose schema changes in a branch PR but MUST NOT:
- Remove fields from `required[]`
- Change `additionalProperties: false` to `true`
- Widen enums by adding unconstrained values
- Change `$id` or `$schema` metadata fields

---

## 4. Invariant IDs: must be registered before use

Before referencing a new invariant ID (e.g. `INV-XXX`) anywhere in code,
the corresponding YAML file MUST exist in `constitution/invariants/` and
be registered in `constitution/constitution.v1.0.yaml`.

AI MUST NOT:
- Invent or use unregistered invariant IDs in TypeScript, Python, or YAML
- Silently change the severity or `non_waivable` field of any invariant
- Remove invariants from the registry even if they appear unused

---

## 5. Failure Codes: closed registry

The failure code registry lives in `constitution/constitution.v1.0.yaml`
under `failure_codes:`. Only registered codes MAY appear in:
- TypeScript source (`reason_code`, `failure_codes[]`)
- Python governance files
- Audit log entries

AI MUST NOT invent new failure codes without adding them to the registry.

---

## 6. Promotion Gate: no silent bypasses

The phase14 promotion gate logic in `tools/phase14_live_fire.ts` and
`phase14/src/phase14/governance_weekly.py` MUST remain fail-closed.
AI MUST NOT:
- Remove invariant checks from the gate
- Add `|| true` or equivalent short-circuits to skip invariant evaluation
- Change `REJECT` defaults to `PROMOTE` defaults

---

## 7. Trust Boundary Enforcement

The following trust zones are defined in the constitution.
AI MUST respect them:

| Zone | Directory | AI Constraint |
|------|-----------|---------------|
| `sovereign` | `constitution/` | READ-ONLY for AI |
| `append_only` | `phase14/data/` | APPEND-ONLY for AI |
| `controlled` | `contracts/`, `tools/`, `tests/` | AI MAY write with PR review |
| `untrusted` | external inputs, adapters | AI MUST validate before use |

---

## 8. Escalation Requirement

If this `.agent.md` file prevents an AI from completing a change the user
requested, the AI MUST:
1. Clearly state which constraint blocks the change
2. Propose an alternative approach via a reviewable PR
3. NEVER silently skip the constraint to complete the task faster
